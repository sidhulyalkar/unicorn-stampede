# v0.36 seeded town grammar

## Design goal

Make repeated campaign runs feel like different visits to the same unruly town rather than unrelated random levels.

The governing rule is:

> Randomize the town's presentation and local tactical relationships without randomizing the play graph.

The player should need to re-read the map, but should never lose because the generator produced an invalid or opaque layout.

## Layers

```text
run seed
  ├─ building dimensions / jitter / hue
  ├─ traffic / people / landmark selection
  ├─ safe whole-town orientation
  └─ deterministic micro-detail
       ├─ building apron
       ├─ footprint shadow
       └─ rooftop utilities
```

The road/crosswalk network remains canonical. The current road grid has exact reflection symmetries around x=1630 and y=930, which permits four whole-town orientations without moving traffic lanes or intersections.

## Why reflection instead of road jitter

Road jitter looks like cheap variety but has expensive consequences: crosswalks, vehicle lanes, district geometry, spawn routes and readable intersections all become coupled to the randomizer. Reflection changes spatial memory while preserving those contracts exactly.

The four orientation states are derived from `runN & 3`; there is no new random state.

## Safety contract

`town-grammar-smoke.mjs` checks four consecutive campaign starts and requires:

- all four orientation states occur;
- seeded lot signatures differ;
- road geometry remains canonical;
- all five landmarks remain assigned;
- applying the same reflection twice restores the layout;
- reflection does not increase the generated layout's road-edge overlap count.

The last rule is deliberately phrased as a delta. The legacy generator checks road clearance before applying its final building jitter, so a small road-edge overlap may pre-exist v0.36.

## Detail strategy

The reference target is visual density through repeated spatial grammar, not a sprite catalogue. Prefer details that appear throughout the town and reuse existing primitives:

1. sidewalk/apron around building footprints;
2. offset footprint shadow;
3. seeded rooftop HVAC/vent boxes;
4. selected-lot service or parking marks if reserve permits;
5. curb/planter rhythm only if it remains visually distinct from gameplay distractions.

Avoid decorative `flowers` objects because flowers are an actual distraction mechanic. Avoid new collision-bearing props unless they are explicitly designed as gameplay.

## Byte rule

Every visual idea pays rent in packed bytes. A repeated primitive that improves twenty buildings is preferable to an equally expensive one-off prop. Keep a meaningful reserve rather than merely reaching 13,312 exactly.

## Future topology frontier

Safe next experiments, in order:

- orientation + seeded landmark permutation (already present through generation);
- district-specific facade/detail rhythm driven by existing hue/position values;
- decorative non-colliding alleys or service pads inside known-safe lots;
- bounded lot archetypes selected from verified road-safe templates;
- only then consider variable road topology, with an explicit connectivity/reachability validator.

A true variable-road generator should be treated as a graph-generation problem, not coordinate noise.
