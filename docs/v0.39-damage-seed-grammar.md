# v0.39 shared visual-seed + damage grammar

## Research question

Can one deterministic per-object visual seed replace duplicated facade hashing **and** pay for more expressive destruction states after Roadroller compression?

v0.35 proved that architectural repetition can create more buildings for fewer bytes. v0.38 proved that invisible work can be exchanged for visible street structure. v0.39 asks whether the same principle can make the town feel more reactive while improving renderer structure.

## Structural observation

The generic building renderer currently derives the same coordinate hash twice:

- `s = o.x + o.y | 0` for lot / roof service marks;
- `g = x + y | 0` later for facade bays, window rows and roof variation.

For buildings, `s` and `g` are identical information expressed through two local variables.

The v0.39 hypothesis is to hoist one deterministic visual seed to the object loop and reuse it for:

```text
lot identity
   +
facade rhythm
   +
rubble silhouette
   +
damage scars
```

No new RNG state is needed. The renderer remains a pure projection of already-existing object state.

## Candidate ladder

### `control`
Exact qualified v0.38 renderer.

Legacy destroyed-building rubble has two alternating height states. Partial damage is represented by one broad translucent fill rising from the bottom of the facade.

### `shared-seed`
Hoist `s=o.x+o.y|0` once per rendered object and reuse it everywhere the generic facade previously recomputed `g=x+y|0`.

Visual intent: identical to control. This candidate isolates whether better dataflow is also better compressed structure.

### `seeded-rubble`
Use the shared seed to change the five rubble-piece heights deterministically.

Legacy rubble effectively has a two-step alternating silhouette. The candidate has 16 seed phases without consuming RNG or adding persistent state.

The replacement is also slightly shorter at source level:

```text
legacy:  parity-based heights
new:     (seed + piece) & 15
```

### `damage-bands`
Replace the large translucent damage rectangle with 1–5 dark structural scar bands as HP falls.

This intentionally tests a more information-dense damage language: damage becomes discrete damaged floors / facade breaks rather than a single color wash.

### `damage-stagger`
Use the same 1–5 damage levels, but seed each scar's left edge so damage reads as irregular structural tearing rather than perfectly horizontal bands.

This is the highest-detail candidate in the ladder.

## Why this might compress well

The candidate does not append a new visual subsystem. It tries to remove duplicate seed derivation and then spend the shared symbol vocabulary repeatedly.

Roadroller often rewards repeated relationships more than isolated source-golf. Here the repeated relationship is:

```text
object position → deterministic visual seed → several render decisions
```

## Safety boundary

Research branch only until paired evidence exists.

No candidate may change:

- object HP, value or collision geometry;
- damage calculations;
- scoring or takeover progress;
- object placement;
- RNG consumption;
- destruction timing;
- particle emission;
- road or town topology.

Only the visual projection of existing object state may change.

## Promotion gates

A candidate is promotable only if:

1. paired ZIP size is no worse than control, preferably clearly smaller;
2. normal gameplay and packed-runtime tests remain green;
3. destroyed buildings have visibly more varied silhouettes;
4. partial damage remains immediately readable during motion;
5. family identity from v0.35 remains legible under damage;
6. the renderer remains pure and deterministic;
7. exact integrated runtime remains <= 13,312 bytes.

If the damage-scar candidates hurt readability, preserve the shared seed / seeded rubble result and reject the scars. More states are not automatically better art.
