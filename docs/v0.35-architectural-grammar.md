# v0.35 research: architectural grammar

## Research question

Can Unicorn Stampede replace enough of the hand-written generic-building facade renderer with a tiny procedural architectural grammar that is **smaller in the final js13k ZIP after Terser + Roadroller + ZIP optimization**, while producing **more distinct buildings**?

The renderer control is inherited from the qualified v0.34 facade implementation, but experiments run against the live v0.35 gameplay/rules branch so paired byte measurements include the current cartridge. Recent v0.35 controls are still over the 13,312-byte cap, which makes this research useful twice: improve the town and recover budget.

## Experimental rule

This is not a source-golf contest. Every candidate is substituted into the same renderer slot and pushed through the real production compression matrix. A shorter JavaScript fragment that produces a larger final ZIP is a loss.

Variation is deterministic from existing building geometry. No new runtime RNG state is introduced, and no experiment changes HP, value, collision, destruction, districts, scoring, or building-family assignment.

## Control

The current generic renderer has five hand-authored facade signatures:

- Bakery: striped awning + storefront bays
- Bank: civic pediment + columns
- Books: masonry courses + display bays
- Cafe: canopy + glazing
- Florist: greenhouse geometry + flowers

The generic facade fragment occupies 1,164 source bytes before minification. Family identity also carries gameplay information because the same family index participates in durability/value scaling, so a promoted grammar must remain readable rather than merely decorative.

## Experiment 1: feature-mask decoder failed after Roadroller

The first candidate generalized the five branches into a shared bitmask interpreter. That looked excellent at source level but lost after packing.

| candidate | facade source | source delta | reachable states | paired ZIP delta |
| --- | ---: | ---: | ---: | ---: |
| control | 1,164 B | 0 | 5 | 0 |
| grammar-compact | 936 B | -228 B | 44 | **+45 B** |
| grammar-depth | 1,037 B | -127 B | 88 | **+60 B** |

This is the first major result: **Roadroller likes the repetitive old branch structure more than a generalized feature-mask VM.** Minimizing source characters is therefore the wrong objective by itself. We need to minimize the entropy and control-flow vocabulary that reaches Roadroller.

## Experiment 2: entropy-friendly grammars

The second tranche removed per-family literal tables and much of the decoder machinery.

### grammar-tiny

`grammar-tiny` keeps more semantic family cues while sharing most geometry:

- hue-derived shell / glass / accent materials
- one variable window rhythm
- arithmetic family grouping for awnings and roof forms
- Books masonry
- Florist flowers
- deterministic roof / window / awning / masonry / flower variation from position

Paired result:

- facade source: **754 B** (`-410 B`)
- reachable descriptor states: **44**
- final ZIP: **13,319 B**
- paired ZIP improvement: **-57 B**
- cap position: **7 B over**

This is a real compression win, but it is not yet legal under the 13,312-byte limit.

### grammar-rhythm

`grammar-rhythm` probes the lower bound: one shared multi-row bay language with family-dependent hue, cornice count, window count, row count, and deterministic rhythm. It intentionally strips more bespoke ornament than we would necessarily ship.

Paired result:

- facade source: **376 B** (`-788 B`)
- reachable descriptor states: **120**
- final ZIP: **13,231 B**
- paired ZIP improvement: **-145 B**
- measured reserve: **81 B**

This is the first clear **Pareto win**: more reachable architectural states and a substantially smaller final Roadroller + ZIP cartridge.

## What the result means

The research hypothesis is viable, but the winning architecture is not "make a generic decoder." The useful shape is closer to a **small repeated visual language whose parameters do the variation**.

There is now a measurable frontier:

`grammar-rhythm` ← 376 B facade, 120 states, 81 B reserve

`grammar-tiny` ← 754 B facade, 44 states, 7 B over cap

The next candidate should live between them. Rather than restoring every old family branch, add only the highest-value family cues whose compressed cost is justified by readability: likely a cheap roof/pediment distinction, an awning distinction, and one signature cue for Books/Florist.

## Compression caveat

Roadroller output has shown small run-to-run variation even for identical source, so paired comparisons are more trustworthy than isolated cartridge sizes. A one-digit win should be replicated before promotion. The `grammar-rhythm` margin is much larger than that noise in the first paired run, but it still requires repeat qualification before integration.

## Promotion gate

A renderer candidate is not production-ready until it satisfies all of the following:

1. final ZIP remains <= 13,312 bytes with meaningful reserve in repeated qualification
2. reachable building states exceed the current five facade signatures
3. the full gameplay and packed-browser regression suite stays green
4. Bakery / Bank / Books / Cafe / Florist remain distinguishable during actual play
5. town silhouettes and openings remain readable under movement, paint, damage tint, and combat clutter
6. no new RNG state or gameplay coupling is introduced

## Current branch status

The research branch intentionally does **not** replace `src/render.js` yet. It contains the repeatable benchmark, CI artifact, and this research record. That keeps the compression lower-bound experiment separate from production art until visual readability is evaluated.

## Next research target

Build a **semantic-mid** grammar between `grammar-rhythm` and `grammar-tiny`, then run an ablation ladder:

`rhythm`
→ `+ roof family cue`
→ `+ awning family cue`
→ `+ Books masonry cue`
→ `+ Florist flower cue`

For each step, measure final ZIP delta and descriptor-state count. Stop adding ornament when the compressed marginal cost becomes worse than the visual information gained.

If that midpoint still fits with useful reserve, integrate only the winning grammar into `src/render.js`, run the complete qualification suite, and then do hands-on art review. The target remains wonderfully strange and concrete: **better architectural variety should pay rent in negative bytes.**
