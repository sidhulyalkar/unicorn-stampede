# v0.38 road-edge grammar

## Research question

Can the road renderer produce **more visible town structure while shipping fewer packed bytes**?

The v0.38 answer is yes, but not by source-golfing every loop. The winning representation deletes invisible work and lets one existing dashed path carry more perceptual information.

## Baseline

The v0.37 street layer contained:

- five canonical road rectangles;
- one dashed gold centerline per road;
- six canonical crosswalk locations, 60 stripe rectangles total;
- a dashed vertical district divider at `WW/2`;
- four low-alpha district fields and labels.

The road geometry is gameplay-sensitive and remains frozen:

```text
[760,0,180,1800]
[1540,0,180,1800]
[2320,0,180,1800]
[0,540,3200,190]
[0,1130,3200,190]
```

## Discovery 1: source characters are not the objective

Several apparently cleaner representations lost after Roadroller:

- arithmetic / branchless centerline geometry;
- derived crosswalk coordinates;
- compact crosswalk loops;
- independent edge strokes.

The explicit horizontal/vertical branch is repetitive enough that Roadroller often likes it. As with the building grammar work, the objective is **compressed entropy**, not raw JavaScript length.

## Discovery 2: the district divider was dead visual work

The old renderer drew a dashed divider at `x = WW/2 = 1600` before drawing roads. The central vertical road spans `x = 1540..1720` and is painted afterward, completely covering that divider.

So v0.37 paid source and compressed bytes for a line the player could not see.

Deleting that occluded stroke is therefore not an aesthetic compromise. It is removal of dead rendering work.

## Discovery 3: the road rectangle can also be the curb grammar

The promoted road loop destructures each road as `[x,y,w,h]` and adds its perimeter to the same dashed path as the centerline:

```text
asphalt rectangle
      ↓
begin one dashed path
      ├── rectangle perimeter
      └── centerline
      ↓
one stroke()
```

This makes the road boundary read as curb / parking / service-edge rhythm without introducing a second material system, RNG stream, object type, or gameplay state.

## Paired compression evidence

Roadroller has modest run-to-run variance, so only same-workflow deltas are meaningful.

### Representation ladder

One paired run:

| candidate | ZIP | delta |
|---|---:|---:|
| control | 13,253 | 0 |
| destructured centerline | 13,259 | +6 |
| destructured edge grammar | 13,244 | -9 |
| derived crosswalks | 13,262 | +9 |

The edge-only result was not stable enough to promote by itself.

### Dead-work exchange

Repeat 1:

| candidate | ZIP | delta |
|---|---:|---:|
| control | 13,241 | 0 |
| dead-divider prune | 13,230 | -11 |
| edge only | 13,259 | +18 |
| prune + edge | 13,234 | **-7** |

Repeat 2:

| candidate | ZIP | delta |
|---|---:|---:|
| control | 13,250 | 0 |
| edge only | 13,262 | +12 |
| prune + edge | 13,238 | **-12** |
| prune + edge + label relocation | 13,238 | -12 |

The combination is the robust result: **delete invisible work, then spend only part of the recovered entropy on visible structure**.

The label relocation was not promoted. It had no packed advantage over the simpler candidate and lacked hands-on placement evidence.

## Promoted runtime

v0.38 promotes exactly two renderer changes:

1. remove the fully occluded vertical district divider;
2. draw each road perimeter and centerline in one shared dashed path.

It deliberately does **not** change:

- road geometry;
- traffic lanes or collision footprints;
- crosswalk geometry;
- district fields or names;
- building placement;
- landmarks, flowers, powerups, people or herd state;
- RNG consumption.

## Frozen contract

`scripts/road-grammar-smoke.mjs` now protects the promoted representation directly. It requires:

- canonical five-road geometry;
- five road-edge paths derived from those road rectangles;
- the original six crosswalk locations and 60 stripe rectangles;
- absence of the hidden divider;
- render purity, verified by comparing gameplay state before and after `world()`.

The contract is part of `npm test` for v0.38.0.

## Design rule carried forward

Do not add decorative systems merely because source code can be golfed.

Prefer this exchange:

```text
remove invisible / redundant work
            ↓
reuse live geometry + live material state
            ↓
add perceptually useful structure
            ↓
measure the final ZIP
```

That is the same deeper principle established by the architectural grammar: **more perceptual information per compressed byte**.
