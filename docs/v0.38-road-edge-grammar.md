# v0.38 road-edge grammar

## Research question

Can the existing road + crosswalk renderer be reorganized so richer street-edge detail costs zero or negative packed bytes?

The target is not to spend v0.37's remaining reserve. The target is to recover bytes by making one road grammar do more jobs.

## Current vocabulary

Each road rectangle currently owns:

- dark asphalt fill;
- dashed gold centerline;
- canonical crosswalks rendered separately at the six known intersections.

The v0.38 hypothesis is that repeated edge rhythm can visually imply curbs / parking / service boundaries if it shares the same dash state already required by the centerline.

## Candidate ladder

1. `control`
   - exact v0.37 renderer.
2. `cross-golf`
   - replace the two explicit crosswalk `fillRect` calls with a tiny two-row loop.
   - visual output should remain equivalent.
3. `edge-gold`
   - use the crosswalk golf;
   - hoist line state out of the road loop;
   - reuse the existing dashed gold stroke to draw each road rectangle edge before drawing its centerline.
   - this deliberately tests whether curb/parking rhythm can be nearly free when it reuses an existing material and dash vocabulary.
4. `edge-muted`
   - same geometry as `edge-gold` but introduces a muted curb material before restoring the gold centerline.
   - expected to look calmer but cost more entropy.

## Safety contract

This tranche is renderer-only research. It may not change:

- `roads` geometry;
- traffic lanes;
- crosswalk coordinates;
- collision geometry;
- district boundaries;
- landmarks, powerups, flowers, people or unicorn state.

A promoted runtime candidate must keep the v0.36 topology smoke and v0.37 render-purity smoke green.

## Compression rule

Judge candidates by same-workflow paired ZIP delta, not JavaScript character count. Roadroller may vary modestly between runs, so tiny single-digit differences should be replicated before promotion.

A detail is especially attractive if it uses an already-live drawing state. Reusing one dash pattern and one material is preferable to adding a new mini rendering subsystem.

## Promotion target

Prefer a candidate that:

1. is no larger than the paired control, or is clearly smaller;
2. gives the roads visibly embedded edges rather than floating gray bands;
3. does not make intersection markings compete with gameplay cues;
4. retains useful reserve under the 13,312-byte cap;
5. keeps all gameplay and renderer-purity tests green.

If no candidate satisfies those gates, preserve v0.37 and treat the benchmark as a negative result rather than spending reserve for decoration.
