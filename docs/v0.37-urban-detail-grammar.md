# v0.37 urban detail grammar

## Question

Can we make the town read as a designed place with lots, districts and rooftop personality without paying for a sprite catalogue or sacrificing the 13 KB cartridge?

The working rule is:

> Reuse one architectural genome across facade, lot, roof and neighborhood context, and place the drawing code where those values already exist.

No new RNG, collision object or gameplay-distraction object is required.

## Current grammar

For every generic building, existing coordinates provide the seed:

```text
x + y
  ├─ 0–3 service / parking ticks
  └─ rooftop utility width + height

quadrant
  └─ subtle pavement / apron identity
```

The four quadrant identities correspond to the existing OLD TOWN, MARKET, GARDENS and RIVERSIDE districts. They change presentation only. Roads, crosswalks, collision footprints, landmark logic, paint quotas and gameplay flowers are untouched.

Every generic building also keeps the v0.36 offset shadow so the city reads as stacked spatial layers rather than rectangles on grass.

## Compression experiments

Roadroller is mildly variable between runs, so compare broad trends rather than one-digit differences.

| experiment | implementation | full qualification | reserve | result |
|---|---|---:|---:|---|
| v0.36 control | fixed apron + shadow + one roof box in wrapper | 13,250 | 62 | qualified base |
| E1 wrapper genome | quadrant apron + parking ticks + variable roof | 13,272 | 40 | fits, but costs bytes |
| E2 structural districts | variable apron + parking count + positional roof dimensions | 13,287 | 25 | rejected |
| E3 shared material wrapper | quadrant apron + shared parking/roof pass | 13,280 | 32 | rejected |
| E4 integrated renderer | same urban vocabulary folded into `drawObjs` | 13,274 | 38 | current candidate |

An independent architecture-contract run for E4 measured 13,238 / 13,312 with 74 bytes free. The conservative full-qualification number is 13,274 because promotion uses the complete exact-head release gate.

The important result is structural: E4 carries richer lot/district/roof information at essentially the same packed scale because it eliminates the extra renderer alias and second traversal over buildings.

## Existing facade contract remains intact

The v0.35 semantic facade grammar is deliberately measured separately from the new contextual layer:

- facade source: 674 bytes
- reachable descriptor states: 120
- five family identities remain structurally distinct
- minimum structural family distance: 2
- zero family-signature collisions

Urban detail is placed before and after that measured facade slice rather than quietly inflating it.

## v0.37 invariant contract

`scripts/urban-detail-smoke.mjs` verifies:

- all four district identities are represented;
- all four 0–3 lot/service-mark states occur;
- rooftop dimensions retain multiple deterministic signatures;
- four campaign seeds retain distinct layouts;
- calling the renderer does not mutate buildings, roads, gameplay flowers or powerups;
- the renderer does not manufacture decorative `flowers` or collision-bearing hedges.

This complements `town-grammar-smoke.mjs`, which protects road geometry, landmark assignment, orientation reversibility and the play graph.

## What this addresses from the reference-city hierarchy

Implemented or partially represented:

1. **Lot personality** through service/parking rhythm.
2. **Roof grammar** through coordinate-derived utility dimensions.
3. **Micro-neighborhood identity** through district-specific apron tone.
4. **Procedural parking/service marks** through tiny repeated rectangles.
5. **Urban depth** through the existing apron + footprint-shadow layers.

Still deliberately deferred:

- road-edge / curb grammar;
- decorative non-gameplay greenery;
- explicit corner architecture;
- richer urban wear / seams;
- true variable road graphs.

Those are not blocked conceptually. They are deferred because the current exact build has only a few dozen bytes of conservative reserve. Future work should first replace or compress existing vocabulary rather than append isolated props.

## Next frontier

The most promising next research order is:

1. recover bytes from existing road/crosswalk rendering;
2. use those recovered bytes for a shared **road-edge grammar** that produces curbs, occasional parking bays and driveway/service cuts from the existing road rectangles;
3. derive a tiny decorative-greenery rhythm only in GARDENS using non-gameplay canvas primitives;
4. test corner accents from already-known road proximity without changing collision geometry;
5. only after those are stable, investigate a validated road-graph generator for genuinely different street networks.

The compression lesson from v0.35–v0.37 is consistent: better art becomes affordable when variation is a parameter of an existing visual language, not another renderer bolted beside it.
